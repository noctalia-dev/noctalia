# Nythera Files standalone independence audit

Nythera Files already runs as its own Wayland client. It has neither a production installation nor a Files-only build configuration. A development executable with the sibling resource bundle and its linked host libraries can launch without a Nythera Shell process, IPC socket or installation. The production gaps are in Meson packaging, installed resource lookup, desktop registration, and ownership of writable settings and the privileged Properties helper.

The audit examined `dev` at `44252e745` with in-progress Properties changes, using the source, configured Ninja graph, Meson install plan, existing debug ELF and local Dev launcher. The Properties changes were subsequently committed as `7d8b029e3`. Runtime conclusions are based on those code paths and build artifacts. No build, installation or GUI test was performed. Links point to repository files, with GitHub line anchors where useful.

## Runtime, configuration and themes

- **Process and platform.** The entry point selects Files assets, validates the startup directory and constructs `FileManager`. It owns a Wayland connection, renderer, GLib poll integration, thumbnail service, timers and native data transfer. The client uses `wl_compositor`, `wl_shm`, `xdg_wm_base` and Wayland EGL/GLES. Clipboard and drag-and-drop require a seat and `wl_data_device_manager`. Cursor and scaling extensions depend on the compositor. The application client filters out layer shell, compositor-specific workspace protocols and Shell clipboard data control. New Window spawns the same executable via `/proc/self/exe`. See [the entry point](src/filemanager/main.cpp#L8), [startup](src/filemanager/file_manager.cpp#L1233), [poll sources](src/filemanager/file_manager.cpp#L1393) and [New Window](src/filemanager/file_manager.cpp#L2124).
- **Writable settings.** `ConfigService` reads Nythera TOML and includes below `$XDG_CONFIG_HOME/nythera`, with the `settings.toml` overlay under `$XDG_STATE_HOME/nythera`. `NYTHERA_CONFIG_HOME` and `NYTHERA_STATE_HOME` override their respective base directories. Home-directory defaults apply. View, sort, layout sizes, saved Places and mount visibility use `[files]` in the shared `state.toml`. Each process loads a snapshot and writes the entire table atomically, so concurrent Files windows or Shell writes can lose updates. The config loader can also persist Shell-schema migrations to the shared overlay. Give Files its own writable state, reuse TOML, migrate only Files preferences and make reuse of existing theme inputs read-only or explicit. Address multi-window writes within the Files state path. See [path selection](src/util/file_utils.h#L375), [config initialization](src/config/config_service.cpp#L571), [overlay migration](src/config/config_service.cpp#L1699) and [state writes](src/config/state_store.cpp#L268).
- **Theme inputs and reload.** The built-in Nythera palette and other presets are compiled in. Files applies its own `ThemeService` and reacts to TOML or overlay changes through the config watcher. It consumes settings such as panel transparency. Custom palettes come from the config directory’s `palettes/` subdirectory, wallpaper palettes use local images and community palettes can use the state cache. Missing or invalid inputs can fall back to a built-in palette. Files creates an `HttpClient` but omits the poll source Shell uses to drive downloads, leaving fresh community palettes without the normal dispatch path. Direct palette JSON edits and desktop icon theme changes also lack dedicated Files watchers. See [theme resolution](src/theme/theme_service.cpp#L429), [custom palette path](src/theme/custom_palettes.cpp#L193), [Files reload](src/filemanager/file_manager.cpp#L1193) and [Shell's HTTP poll registration](src/app/application_poll_sources.cpp#L65).

## Assets and install lookup

**Confirmed blocker.** `nythera-file-manager` sets `install: false`. The Files asset recipes populate a build-tree bundle only. The Files resolver selects one root for the process from `NYTHERA_ASSETS_DIR`, sibling `files-assets/`, sibling `assets/` or `../assets/` relative to the real executable. The display font and English catalogue are the markers. Files never tries the compiled install datadir. Shell has a separate resolver and installs its assets under `${datadir}/nythera/assets`. Enabling executable installation or copying assets into `share/` alone leaves Files unable to find its required display font. See [resource lookup](src/core/files/resource_paths.cpp#L52) and [Meson install rules](meson.build#L1239).

| Resource | Current coverage and production requirement |
| --- | --- |
| Fonts and glyphs | The Dev bundle includes `NytheraDisplay-Regular.ttf`, `nythera-tabler.ttf`, `tabler.json` and the Tabler licence. A missing or invalid display font fails renderer initialization. Tabler failure is tolerated but affects controls and fallback glyphs. Install all four together. Body text uses system Pango/Fontconfig fonts with a sans-serif default. See the [font manifest](files-assets/fonts/meson.build#L1), [renderer initialization](src/render/render_context.cpp#L102) and [glyph catalogue](src/render/text/glyph_registry.cpp#L163). |

It falls back to generic glyphs. The Dev bundle provides glyphs. Rich artwork depends on the host icon theme and MIME data. See [GIO artwork](src/ui/dialogs/file_artwork.h#L71), [theme search](src/system/icon_resolver.cpp#L528) and [glyph fallback](src/ui/dialogs/file_icon.h#L117). |

## Functional and desktop integration

| Feature | Requirements and limits |
| --- | --- |
| Local and mounted files | In-process GIO enumeration, monitors and worker operations cover browsing, copy, move, rename, creation and deletion. Mounted NFS, SMB/CIFS and similar shares use accessible local paths and host permissions. Places merges GIO and Unix mount information. GIO mounts need a native path to appear as browsable locations. General remote URI browsing and NFS provisioning are outside the current contract. See [enumeration](src/filemanager/file_manager.cpp#L1483), [Places discovery](src/filemanager/places_model.cpp#L510) and [file operations](src/filemanager/file_operation_manager.cpp#L1533). |
| Mount actions and Wastebin | Mount/eject uses GIO and native credential/question prompts. Unmount can use UDisks2 or systemd over the system bus with host authorization, or the applicable `/usr/bin/umount` and `/usr/bin/fusermount3` paths. Wastebin browsing, restore and empty need a `trash:///` provider, typically GVfs and a session bus. Moving to Trash also depends on filesystem support and permissions. See [mount prompts](src/filemanager/file_manager.cpp#L2736), [unmount dispatch](src/filemanager/places_model.cpp#L776), [managed backends](src/filemanager/mount_backends.cpp#L10) and [Wastebin operations](src/filemanager/file_operation_manager.cpp#L271). |
| Clipboard and drag-and-drop | Native Wayland data devices carry `text/uri-list`, GNOME copied-files and KDE cut-selection formats. The process persists while holding a selection or finishing transfer work after window close. Verify interoperability with the compositor and peer app. See [transfer formats](src/filemanager/file_transfer_payload.cpp#L10), [data device](src/wayland/native_data_transfer.cpp#L434) and [process lifetime](src/filemanager/file_manager.cpp#L1395). |
| Thumbnails and Properties | Thumbnails use an in-process decoder and disk cache without an external thumbnailer. Metadata, size scanning and permitted edits work locally. Elevated changes require the helper, its registered `dev.nythera.Files.modify-properties` policy, `/usr/bin/pkexec`, Polkit and a desktop agent. The client checks trusted root-owned paths and the policy's helper annotation. A user-prefix install can run Files but cannot provide elevated edits under that prefix. See [thumbnails](src/render/core/thumbnail_service.cpp#L496), [helper checks](src/filemanager/property_operation_client.cpp#L10) and the [policy](data/polkit/dev.nythera.Files.modify-properties.policy.in#L5). |
| Open With and progress | GIO handles MIME lookups and launches. Properties can explicitly set a MIME default. Files already displays transfer status, cancellation and progress in its native UI. Desktop notifications and KDE job publishing would be new behavior. See [Open With](src/filemanager/file_manager.cpp#L1691), [MIME default operation](src/filemanager/property_operation_client.cpp#L163) and [progress window](src/filemanager/file_manager.cpp#L4323). |

Keep the production executable name `nythera-file-manager` and match the Wayland ID with `dev.nythera.FileManager.desktop`. Use a named icon, `Exec=nythera-file-manager %u`, `TryExec=nythera-file-manager` and `MimeType=inode/directory;`. The current CLI accepts zero or one accessible directory path or local `file:` URI. Multiple inputs, arbitrary files, remote URI schemes and D-Bus activation are outside that contract. Verify grouping and icon resolution for the existing `.Properties`, `.Progress` and `.Dialog` IDs. Keep the local `dev.nythera.Files.Dev.desktop` launcher separate with its checkout path. Its desktop filename already differs from the current Wayland ID, so test coexistence explicitly. Registration should leave `mimeapps.list`, Dolphin and the default file manager alone. See [startup parsing](src/filemanager/startup_path.h#L11), [main window ID](src/filemanager/file_manager.cpp#L1303) and [Wayland ID setter](src/wayland/toplevel_surface.cpp#L75).

The existing `just install` requires the Shell binary and installs the Meson project. `just uninstall` uses the build directory’s install log. The Nix derivation packages Shell and the release workflow produces repository source tarballs. The inspected tree has no Files-specific package manifest, release artifact or AppStream metadata. A split package needs a single owner for the helper and policy, which the full Meson install already claims. Paths and ownership must agree across upgrades, especially when Polkit’s policy directory is outside the Meson prefix. Remove package-owned files on uninstall and preserve user settings. See [install recipes](justfile#L65), [helper install rules](meson.build#L1213), [Nix package](nix/package.nix#L64) and [release workflow](.github/workflows/release.yml#L40).

## Packaging strategy and roadmap

| Approach | Restructuring, maintenance and release trade-offs |
| --- | --- |
| A. Package Files from the full monorepo build | Add installable Files outputs and resource lookup within the existing graph. Low restructuring cost and immediate sync with Shell. Builders still need Shell dependencies. Viable first packaging milestone with its own staging manifest and measured release ELF dependencies. |
| B. Independently buildable Files component in the monorepo | Gate Shell sources, dependency probes, generated protocols, tests and install outputs in Meson. Keep private shared libraries in-tree with explicit dependencies. Shared fixes remain atomic. Dedicated CI can build with Shell development libraries absent and publish separate artifacts from the same source release. |
| C. Separate repository | Version the shared UI, Wayland, configuration, theme and resource code or maintain synchronized vendoring. Independent ownership and release timing come with cross-repository compatibility testing and version coordination. |

**Recommend B, staged through A.**

1. **Functional standalone install.** Add a production data directory such as `${datadir}/nythera-files` to Files lookup and reuse the bundle manifest for installation. Preserve Dev lookup. Verify normal and custom prefixes from outside the checkout. Give Files ownership of its writable state and define compatibility for existing preferences and theme inputs.
2. **Desktop integration and release packaging.** Install the executable, data, desktop entry and icon as a cohesive package. Define ownership and version compatibility for the helper and policy. Declare mandatory libraries and feature-specific host providers. Verify package coexistence, upgrades and removal. Restore HTTP polling if fresh community palettes are part of release parity. Handle direct palette and desktop icon theme watching separately.
3. **Files-only build.** Gate irrelevant probes and targets using an explicit Files source and shared-library closure. Split mixed translation units where they retain unwanted dependencies. Verify release ELF dependencies and staged manifests in CI. Consider a repository split only if independent ownership or release cadence warrants maintaining shared interfaces across repositories.

## Verification plan

1. Configure and build Files on a clean system without Shell development packages. Inspect the target graph, ELF dependencies and staged install manifests under standard and custom prefixes. Validate desktop metadata and match the helper and policy paths.
2. Run on a clean Wayland system with no Shell process, binary, configuration, assets or checkout. Leave Nythera overrides unset. Launch from the menu and an unrelated directory. Test paths, encoded local URIs, invalid arguments and New Window. Check main and child IDs, fonts, icons, locale fallback, RTL and dialog artwork on Umbriel and a second compositor.
3. Exercise local and cross-filesystem jobs, mounted NFS, GIO-managed mounts and authentication, Wastebin restore and empty, clipboard and drag-and-drop in both directions, thumbnails, ordinary and elevated Properties, Open With, all three office templates, progress and cancellation. Repeat relevant cases without optional providers to check feature availability and errors.
4. Verify built-in themes offline, config-triggered reload, custom palettes, wallpaper fallback and a cold community cache if supported. Test concurrent Files windows and Shell coexistence for persistence. Compare MIME defaults before and after installation, upgrade and removal. Confirm the Dev launcher, user preferences and other file managers remain present. Use the existing [focused Meson tests](meson.build#L1711) alongside the installed-app checks.
