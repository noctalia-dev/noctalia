# Nythera customisation and compatibility register

This document records **behavioural contracts**, not a frozen list of code to keep forever. During upstream integrations, preserve Nythera's intended behaviour while replacing obsolete implementations when needed. Use [REBRAND.md](../REBRAND.md) for identity, external APIs and migration contracts; [ARCHITECTURE.md](../ARCHITECTURE.md) for architectural invariants; and [SCOPE.md](../SCOPE.md) to distinguish committed scope from future ideas.

Entries below are based on project documentation and must be confirmed against the local implementation before an integration. Do not treat a documented intention as proof that every aspect is implemented.

## Shared nebula background

**Implemented; runtime validation tracked in [the background guide](nebula-background-poc.md).** Preserve the accepted dark crimson appearance, slow movement, independent native-surface switches and background-only transparency. The dedicated Haze section uses existing `shell.panel.haze_*` persistence. Bars/islands stay clear, including in joined contours. Owners: `src/render/animation/surface_haze.*`, `src/render/programs/nebula_glsl.h`, native Surface lifecycle and tagged Box/Flex/screen-frame materials. Upstream surface, contour, frame-callback or settings refactors must preserve these contracts. Comprehensive performance benchmarking remains issue #18 work.

## Discord / Vesktop template

The opt-in **Discord / Vesktop** built-in template ships Nythera's System24 stylesheet with pinned System24/Midnight dependencies, MIT notices and embedded artwork. It follows the application palette, leaves client theme selection manual, and removes only its generated `nythera.theme.css` when disabled. Owners: `assets/templates/discord/`, `assets/templates/builtin.toml`, `tools/build-discord-template.py`. Default configuration selects no built-in templates. Implementation uses the existing template engine; live client reload and visual acceptance require checking after CSS or upstream selector changes. See `docs/user/templates/official/discord.mdx` for setup and maintenance.

## Nythera Files

**Implemented; native interaction and real-device acceptance require runtime checks.** The standalone C++ file manager preserves local browsing, selection, staged transfers and conflict dialogs while adding model-backed Places, capability-based device menus, saved local folders and reordering, GIO Wastebin browsing, virtualised rubber-band selection with edge scrolling, internal file drags with pointer previews, unified persistent group ordering/drag-to-pin, independent artwork zoom and explicit symlink type/target presentation. Owners: `src/filemanager/`, `src/ui/controls/virtual_grid_view.*`. See [Places and file interaction](FILE-MANAGER-PLACES.md) for persistence, input, virtual-namespace and device-safety contracts. Cross-application drag-and-drop, Restore and Empty Wastebin are not implemented.

**Stage 1.5 Edit menu.** File and Edit remain accessible when the window is narrow or the saved menu-bar preference hides the header menus. Edit includes clipboard, selection and file actions. Selection commands apply to the filtered list or grid, including Wastebin contents. Duplicate uses the staged Copy worker with numbered names. Create New offers immediate absolute symlinks to a selected regular file or folder and a manual symlink form. Manual symlink targets and address bar paths expand a leading `~` or `~/` to the current user's home directory. Other inputs follow the existing path handling. The latest GUI corrections await native verification.

Undo and Redo retain up to 32 committed items per window. A batch contributes one entry per reversible item, including items that finished before a failure or cancellation. History includes new empty files and folders, symlinks, eligible no-replace renames, simple same-filesystem moves and regular-file or symlink copies and duplicates. Each replay verifies the recorded item and parent identities, checks change metadata and uses native no-replace moves. A new forward change clears Redo. Recursive transfers, replacements, merges, Properties changes and Wastebin actions have no replay entries. Permanent Delete and Empty Wastebin remain irreversible. History ends when the Files process exits.

**Stage 1.5 View menu.** The header and hamburger share the View commands for display mode, sorting, hidden files, zoom, refresh and menu-bar visibility. List View retains the existing header-boundary resizing and stores width, visibility and position by column. Name remains visible and can be reordered. Existing saved widths for Name, Size and Modified carry forward. Optional metadata columns fit within the list viewport and show a dash for unavailable values. Show Columns can be edited in either view and applies to List. The Size column counts immediate folder entries in the background and shows a dash if a count is unavailable. The counts are display-only. Grid keeps its existing tile presentation. Native interaction awaits verification.

**Stage 1.5 checksum tools.** Calculate and Verify are available for a single regular local file. They stream SHA-256, SHA-512 or MD5 in a cancellable background job and reject final symlinks and files that change while being read. Verify accepts a pasted hash, a manifest containing one bare hash, or a GNU-style manifest with text or binary markers and escaped filenames. Manifest suffixes suggest the algorithm, and other suffixes can be used with a manually selected algorithm. Files matches bare names against the selected basename and relative subpaths against the manifest directory. Absolute paths and parent traversal entries are ignored. Only the selected file and the explicitly chosen manifest are opened. Manifests are limited to 4 MiB. Owners: `src/filemanager/checksum.*` and `src/filemanager/file_manager.*`. Native interaction awaits verification.

The native single-item Properties window (`properties_window.*`) retains the approved General, Permissions and Details layout, async metadata without following symlinks, mount-target storage usage, editable filenames, saved dimensions, scrolling and fixed actions. It stages R/W/X, local owner/group and MIME default-application selections until Apply; metadata refreshes after execution. Recursive permission masks use bounded traversal without symlinks or mount crossings, preserve regular-file execute bits and report partial results through the existing file-operation jobs. A dedicated Polkit helper handles authorised metadata changes without elevating Files itself; installation and real privileged integration remain unverified. GIO descriptions identify file types; literal filename suffixes remain separate from MIME types. Metadata values support native read-only selection and copying, with expandable long values and hover-only path copy controls. Ordinary value tooltips are removed; filename edits participate in footer Apply. Ownership uses native selects and permissions use aligned checkbox columns. Directory Properties automatically calculates logical contents size in a cancellable, bounded worker without following links or crossing child mounts. Results are cached across tabs; incomplete totals are labelled Partial. Ordinary success messages are removed and errors remain beside their controls. See [Files Properties](FILE-PROPERTIES.md) for privilege, traversal, cancellation and installation contracts. Visual and interaction acceptance remains subject to manual review.

**Files Administrator Mode.** Tools → Act as Administrator elevates the current tab after Polkit authentication. A folder’s Open as Administrator action authenticates and then opens the folder in the originating tab. The header displays a Warning-coloured shield, Administrator Mode and Finish. Elevated tab labels use the Warning role and the active tab’s window title includes `[Administrator]`. New, duplicated and reopened tabs and new windows start with ordinary access. Finish, helper failure and expiry cancel any active inline rename, discard cached privileged metadata and reopen the current directory through the ordinary backend when accessible, with the default opening location and a safe fallback otherwise.

The dedicated `dev.nythera.Files.admin-session` action runs a root-owned helper over private pipes. The graphical Files process runs as the signed-in user. The helper serves bounded directory batches, entry metadata, immediate counts and filesystem capacity. Elevated browsing uses explicit refresh and preserves selection and post-creation inline rename. The helper enforces an inactivity limit of 600 seconds by default. The Files state key `admin_inactivity_timeout_seconds` accepts 60–3600 seconds. Meaningful user interaction and advancing operation progress renew the deadline. Background refreshes and health checks leave it unchanged.

Writable Administrator tabs can create folders, empty files, text files and symlinks, rename and duplicate items, paste copied or cut items, and permanently delete selected items after confirmation. Copy and Cut use the existing file clipboard. Paste into a writable Administrator tab uses that tab’s session. Wastebin, templates, drag-and-drop, file launching, external tools, Properties, checksums, pinning and Undo/Redo remain unavailable in Administrator Mode.

`FileOperationManager` coordinates these mutations through the session-bound protocol v6 transport, with up to 1,024 source paths per operation and a 64 KiB limit per frame. The helper executes the shared filesystem engine under its authenticated credentials. The engine resolves filesystem paths and provides the existing conflict dialogs with metadata, including Replace, Merge, Keep Both, Skip, Cancel and applicable batch decisions. Progress, pause, resume, cancellation and completion use the existing job controls. Finish, tab closure and expiry cancel and drain the worker. The client retains received records and marks an incomplete result uncertain when the connection fails. Legacy mutation handlers remain available in the protocol implementation for regression coverage.

Owners include `directory_session.*`, `browser_tab.*`, `admin_session_client.*`, `admin_protocol.*`, `admin_helper_session.*`, the Files menu and transfer controllers, and `file_operation_manager.*`. The standalone Files binary and the installed helper must use the same protocol version. Native Polkit and Wayland acceptance require an owner-run integration check.

**Help menu.** Both the application menu bar and the collapsed hamburger menu expose Help with Keyboard Shortcuts, Report a Bug…, Nythera Files on GitHub and About Nythera Files. Keyboard Shortcuts displays a scrollable, read-only reference of implemented shortcuts grouped by function inside the native dialog chrome (`ModalDialogHost`), including `Ctrl+Shift+N` (`New Folder`, matching both shifted `XKB_KEY_N` and lowercase `XKB_KEY_n`). Report a Bug… and Nythera Files on GitHub open the GitHub issues overview (`https://github.com/Nythera-Dev/Nythera/issues`) and repository (`https://github.com/Nythera-Dev/Nythera`) in the default browser via `net::openInBrowser`, and About Nythera Files presents the Nythera Files icon (`concepts/nythera-files-icon.png`), Nythera Display branding, build version (`nythera::build_info::displayVersion()`), Nythera Files MIT licence (`Copyright © 2026 Kangy`), Noctalia infrastructure credits (`Copyright © 2026 noctalia-dev`), and a clickable repository link. Standalone Files bundles `files-assets/LICENSE` alongside its runtime assets. Owners: `src/filemanager/dialogs/help_dialog.*`, `src/filemanager/file_menu_controller.*` and `src/filemanager/dialogs/modal_dialog_host.*`. Live native visual verification remains pending.

## Updating the register

- When a Nythera feature is added, substantially redesigned or retired, update its entry (or add one) in the same change.
- Record the **visible/user contract**, owning files or symbols confirmed from source, and upstream dependencies. Prefer stable paths/subsystems over brittle line numbers.
- Label entries **verified implemented**, **experimental**, **planned** or **unverified** as appropriate. Do not promote an item solely because it appears in a README.
- Upstream integration reports should identify entries affected, how their behaviour was verified, and any explicit deferrals.
- This file does **not** override user decisions, `ARCHITECTURE.md`, `REBRAND.md`, or the need to inspect live code. It is a navigation aid for agents.
