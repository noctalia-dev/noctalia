# Nythera Files: Places and file interaction

The standalone native file manager owns these interactions in `src/filemanager/file_manager.*`, with discovery and device operations in `places_model.*` and file transfers in `file_operation_manager.*`.

- The sidebar divider uses a surface-local logical-coordinate delta from the original press. Wayland's implicit button grab retains the gesture until release; Escape cancels it. Hover/drag use the horizontal resize cursor and a palette-aware highlight. Width persists in the existing `files` state table.
- Personal locations come from GLib's configured XDG directories. Valid directory symlinks are accepted; canonical targets are deduplicated. Missing or broken locations are omitted without creating anything. Categories configured as Home are deduplicated against Home, even if separate conventional symlinks exist.
- Wastebin browses the GIO `trash:///` namespace, including child folders. Internal history tokens are explicitly routed to GIO URIs and never passed to local file operations. Original locations appear in tooltips where the backend supplies them. Refresh is explicit; Restore and Empty Wastebin are not implemented.
- Folder and directory-background menus can add local folders to Places, with a chosen display name. Saved entries use independent UUIDs and retain their chosen absolute paths (including valid symlinks); their names, identities and order persist together through the existing TOML state store and atomic writer. Removing an entry does not remove the folder. All rows can be reordered within their existing Personal, Devices or Network group; insertion lines indicate positions. Built-ins and pinned folders share one Personal sequence. The separate `place_order` identity list retains disconnected resources and persists through the existing state store. Initial Devices and Network discovery places mounted resources first, then sorts by human-readable label; newly discovered unsorted resources follow the saved sequence alphabetically. GIO volume UUID identities remain stable across mount/unmount and mount-path changes. Dragging local folders into Personal insertion strips pins them without transferring files; the centre of folder rows remains an ordinary transfer target. Duplicate canonical folder targets are rejected while bookmark paths retain valid symlink spelling.
- NFS, SMB and SSHFS use Network. Other local FUSE mounts, including rclone, use Devices. Mounted and unmounted devices share the user-defined order. Unmounted volumes use a compact single row with a muted label, the existing themed device icon and a small themed disconnected indicator. Their tooltip exposes the unmounted status; mounted capacity rows are unchanged.
- Device and Network rows offer Hide from Places, including unmounted volumes. Hidden identities persist in `files.hidden_mounts` through the existing state store and retain their saved order. Right-click either group heading and enable Show hidden mounts to reveal rows marked `(hidden)`; their Show in Places action restores them permanently. The reveal toggle lasts for the current Files window. Hiding affects only sidebar presentation: discovery, mount operations, current-location tracking and transfer protections remain active. Personal folders retain their existing bookmark removal actions.
- Device menus prefer GIO-supported mount, unmount and eject operations. User-owned FUSE mounts retain `/usr/bin/fusermount3 -u`; matching fstab entries with `user`/`users` retain unprivileged `/usr/bin/umount`. Helpers receive argument vectors and never force/lazy flags, shell text or elevated privileges. Helper errors are translated into short busy/permission/failure messages. Unmounted devices retain Mount where GIO advertises it; Unix-only disconnected entries are not invented.
- Optional UDisks2 D-Bus discovery adds Unmount for isolated local block filesystems. Device aliases are resolved before comparing mount sources. Filesystems with multiple mount views, Btrfs subvolumes and bind roots never use this filesystem-wide fallback. Systemd D-Bus discovery adds Unmount for matching active mount units, including NFS and exact Btrfs/bind mount points, only when the unit allows manual stopping, has no reverse required/bound/part-of/stop-propagation dependencies and enables neither force nor lazy unmount. Required mount units, including mounts required by filesystem targets, deliberately remain unsupported through this fallback. Unix mounts without an eligible GIO, user helper or service backend remain unsupported. No library/package dependency, Polkit rule, systemd unit or mount configuration is added.
- System filesystems are protected before accepting any backend's capabilities. Protection covers root, Home, boot/EFI and system trees, ancestors containing relocated critical paths and the active user's home. Eject additionally checks the physical drive's known volumes and mounted sibling partitions; ambiguous drive/device-mapper topology is excluded. Shared block-device GIO operations are suppressed in favour of an eligible exact mount unit. Duplicate GIO/Unix paths retain one menu and existing presentation. Backends are discovered off the UI thread and refreshed from mount/volume and service-availability events, without periodic polling.
- UDisks2 and systemd perform privileged authorisation through the existing desktop Polkit agent. Files never collects a root password or launches a privileged command. Dispatch revalidates the backend, mount source/path/type/root and safety policy. Systemd completion waits for the matching JobRemoved result rather than treating a queued stop job as success. Requests are serialised across Files windows; once dispatched, the operation guard is held until the service/helper finishes (or reports a timeout), including caller cancellation. Denial, cancelled authorisation, busy resources, disappeared devices and unavailable services produce concise failures. Native GMountOperation prompts continue to handle GIO credentials without saving passwords. Busy requests never force removal or kill processes. Transfers protect every source/destination mount until their workers finish; eject waits for all transfers. Successful completion refreshes Places through its existing lifecycle.
- Internal pointer drags preserve selected files and folders and accept folder, saved-Place and mounted-device destinations. They use the existing staged transfer manager, conflict dialogs, cancellation and notifications. Self and recursive drops are rejected, including aliases through symlinks. The default is move on the same filesystem and copy across filesystems; Ctrl copies and Shift moves. Escape cancels the drag. Cross-application Wayland DnD is absent.
- Ctrl+vertical wheel over the file view adjusts its persistent scale from 80% to 180%. List rows start at 32 logical pixels with a one-pixel gap; grid cells use 106-pixel height. Fonts, icons and geometry scale together. Normal scrolling and sidebar/UI scale are unchanged; inline rename defers zoom.

Focused fixture tests cover configured XDG symlinks and deduplication, discovery signal routing, unsupported device operations, drop-target safety, all-source transfer mount tracking, and cancellation completion timing. These tests do not prove real-device lifecycle or native visual/input correctness; record live verification separately when changing these interactions. Use disposable fixtures and removable test media for operation tests.
