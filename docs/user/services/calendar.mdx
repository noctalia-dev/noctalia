The calendar service syncs read-only events from online accounts or local calendar directories and shows them in the control center calendar. Set it up in **Settings → Calendar**.

- CalDAV providers (Nextcloud, iCloud, Fastmail, Radicale, mailbox.org, …) are reached directly.
- Google Calendar connects through a browser authorization flow.
- Local vdir directories (such as vdirsyncer) are watched for changes.

`[calendar]` covers account sync, duplicate merging, event date and time formats, and [event reminders](#reminders). Calendar-tab options such as the events card and ISO week numbers live under [`[control_center.calendar]`](/noctalia/control-center/#calendar).

Clicking an event with an `http` or `https` link opens it in your default browser:

- A meeting link in the event location wins, then a provider meeting link (such as a Teams join link) in the description, then a generic event URL.
- Google events without a meeting link open in Google Calendar.
- Reminder notifications only open meeting links.

## Settings setup

1. Open **Settings → Calendar → Accounts → Add Account**.
2. Choose the account type and fill in its fields:
   - **iCloud**: a local account id such as `personal_icloud`, your Apple Account email, and an Apple app-specific password.
   - **CalDAV**: a local account id such as `home_nextcloud`, the provider's CalDAV discovery root, your username, and a provider app password.
   - **Google**: a local account id such as `work_google`, then press **Save and Connect**. A browser opens for Google authorization.
   - **Local (vdir)**: a local account id such as `local_vdir` and the directory path (e.g. `~/.local/share/calendars`), then press **Save**.
   - **ICS URL**: a local account id such as `subscription`, then press **Save**.

Saving an account enables `[calendar]` automatically and writes a named table such as `[calendar.account.personal_icloud]` to `settings.toml`.

- CalDAV passwords use the account's [credential source](#credential-storage): Secret Service by default, or one password file.
- Google refresh tokens are stored in Secret Service; access tokens stay in memory only.
- The last synced events are cached [encrypted](#event-cache-encryption).

Account ids are local to Noctalia. Use lowercase letters, digits, and underscores only. Settings keeps an id fixed after creation so config and credential keys are never orphaned.

To edit an account, open **Settings → Calendar → Accounts**.

- Google accounts have the same name and color editor, plus **Save** and **Save and Connect**. Both save the editor values; **Save and Connect** then opens browser authorization.
- Delete is offered only for accounts created in `settings.toml`. Accounts declared in `~/.config/noctalia/*.toml` are never removed by Settings.

## Manual setup

```toml
# Enable the calendar and add one account of each type
[calendar]
enabled                = true
dedupe_events          = false
dedupe_ignore_patterns = []
refresh_minutes        = 15
event_date_format      = "%A %e %B"
event_time_format      = "%H:%M"

# iCloud CalDAV. The table name is the local account id.
[calendar.account.personal_icloud]
type     = "caldav"
name     = "Personal iCloud"
provider = "icloud"
username = "you@example.com"
color    = "primary"        # color role or hex color
calendars = []              # empty = all discovered

# Generic CalDAV discovery root
[calendar.account.home_nextcloud]
type       = "caldav"
name       = "Home"
provider   = "custom"
server_url = "https://cloud.example.com/remote.php/dav/"
username   = "me"
calendars  = ["personal"]   # discovered collection ids
credential_source = "file"
password_file = "/run/agenix/noctalia-caldav"

# Google Calendar (connect in Settings)
[calendar.account.work_google]
type = "google"
name = "Work"
calendars = []              # empty = Google sidebar ticks

# Local vdir directory (vdirsyncer / khal)
[calendar.account.local_vdir]
type = "vdir"
name = "Local Calendars"
path = "~/.local/share/calendars"
calendars = []

# ICS subscription
[calendar.account.holidays]
name = "Canadian Holidays"
server_url = "https://canada-holidays.ca/ics?cd=true"
type = "ics"
color = "#FF0000"
```

| Key                      | Default      | Description                                                                                                       |
| ------------------------ | ------------ | ----------------------------------------------------------------------------------------------------------------- |
| `enabled`                | `false`      | Turn on calendar sync.                                                                                            |
| `dedupe_events`          | `false`      | Merge an event that appears in more than one calendar. See [Merging duplicate events](#merging-duplicate-events). |
| `dedupe_ignore_patterns` | `[]`         | Regexes stripped from titles before events are compared.                                                          |
| `refresh_minutes`        | `15`         | Minutes between syncs.                                                                                            |
| `event_date_format`      | `"%A %e %B"` | Date format for events.                                                                                           |
| `event_time_format`      | `"%H:%M"`    | Time format for events.                                                                                           |

Account tables (`[calendar.account.<id>]`) take these keys:

| Key                                   | Applies to  | Description                                                                 |
| ------------------------------------- | ----------- | --------------------------------------------------------------------------- |
| `type`                                | all         | `caldav`, `google`, `vdir`, or `ics`.                                       |
| `name`                                | all         | Display name.                                                               |
| `color`                               | all         | Optional color role or hex color.                                           |
| `calendars`                           | all         | Calendar ids to sync; empty = all (Google: the ones ticked in its sidebar). |
| `provider`                            | caldav      | `icloud` or `custom`.                                                       |
| `server_url`                          | caldav, ics | CalDAV discovery root, or the ICS URL.                                      |
| `username`                            | caldav      | Account username or email.                                                  |
| `credential_source`, `password_file`  | caldav      | See [Credential storage](#credential-storage).                              |
| `client_cert_file`, `client_key_file` | caldav      | See [mTLS](#mtls-client-certificates).                                      |
| `path`                                | vdir        | Calendar directory.                                                         |

:::caution
Credentials are never stored in your config. `password_file` holds only a path; the file holds the CalDAV password.
:::

## Sync status

Each account row in **Settings → Calendar → Accounts** shows whether it is syncing, when it last synced, or why the last sync failed.

- Most failures are fixed with **Edit**.
- A locked keyring: unlock it, then **Retry**.
- A Google account with missing or revoked authorization: **Reconnect**.

Failed syncs are retried at the refresh interval, and the last synced events stay shown meanwhile.

## Merging duplicate events

`dedupe_events` (**Settings → Calendar → General → Merge Duplicate Events**) shows an event once when it appears in several of your calendars, in one account or across accounts.

- Two events match when their start, end, all-day flag, and title match.
- The copy kept has the most filled-in fields (color, link, location), then the longer title.

`dedupe_ignore_patterns` is a list of case-insensitive ECMAScript regexes removed from titles before comparing, so slightly different wordings still merge. The more detailed title is displayed.

- To ignore a trailing parenthetical, use `['\s*\(.*\)$']`; TOML single quotes keep the backslashes literal.
- An invalid pattern is skipped.

## Reminders

Noctalia can notify you before an event starts. Reminders come from the calendar itself (`VALARM` triggers on CalDAV, ICS, and vdir events; reminder overrides or calendar defaults on Google), with a fallback for events that carry none.

```toml
# Event reminder defaults
[calendar.reminders]
enabled              = true
use_event_reminders  = true
default_lead_minutes = 10
all_day_digest_time  = "09:00"
```

| Key                    | Default   | Description                                                                                        |
| ---------------------- | --------- | -------------------------------------------------------------------------------------------------- |
| `enabled`              | `true`    | Show event reminders. Requires `[calendar]` to be enabled.                                         |
| `use_event_reminders`  | `true`    | Honor per-event reminders. `false` applies `default_lead_minutes` to every event.                  |
| `default_lead_minutes` | `10`      | Lead time for events without their own reminder. `0` = at event start.                             |
| `all_day_digest_time`  | `"09:00"` | Local time (24-hour `HH:MM`) of one notification listing today's all-day events. `""` disables it. |

Settings → Calendar → Reminders.

- A Google event whose notifications you removed stays silent. A declined Google event still shows in the calendar but never reminds and is left out of the digest, even with `use_event_reminders = false`.
- Google events on a calendar without default notifications use `default_lead_minutes`.
- The notification counts down as the event approaches and ends on "Starts now". Clicking it opens the event's link if it has one.
- All-day events never notify individually; they go in the daily digest. Starting the shell after the digest time still shows that day's digest, and calendars that sync later are not skipped.
- A reminder missed while the shell was off fires at startup if the event has not started yet. Reminders for events already begun are dropped.
- Reminders stay in notification history and follow Do Not Disturb.
- Reminder times come from the encrypted event cache, so they work offline and across restarts.

## Credential storage

:::note
Each CalDAV account has exactly one credential source, and Noctalia never falls back from one to the other.
:::

- `credential_source = "secret-service"` (default): enter the password in Settings. Needs a Secret Service provider in the login session, such as GNOME Keyring, KWallet, or KeePassXC. `libsecret` alone does not start a provider.
- `credential_source = "file"`: requires an absolute `password_file`, read on every sync. One trailing LF or CRLF is ignored. Empty files, NUL bytes, non-regular files, and files over 64 KiB are rejected.
- `password_file` is rejected unless `credential_source = "file"`, and file mode is rejected without an absolute `password_file`.

File credentials work with agenix, sops-nix, and systemd credentials. Make the decrypted file readable by the user running Noctalia; Noctalia never edits or deletes it. Google refresh tokens always require Secret Service.

CalDAV passwords and Google refresh tokens go to the Secret Service `default` collection, which must be unlocked at login. With several GNOME Keyring keyrings, a locked `default` is the usual cause of credentials locking after every reboot. See [Secret Service & keyrings](/noctalia/configuration/secret-service/) for the fix and automatic recovery.

- If a matching credential stays locked after an unlock attempt, Noctalia sends one notification and marks the Google account as locked. Unlock the keyring and use **Retry**. Do not reconnect unless Settings says authorization is missing.
- A Google account with no refresh token shows **Reconnect**.
- A cache-key warning is about the event cache, not your Google authorization.

## Event cache encryption

:::note
Event titles, locations, names, and times are written only to the encrypted `$XDG_CACHE_HOME/noctalia/calendar/events.enc` cache, keyed from the shared storage master key.
:::

By default (`[storage].key_source = "secret-service"`) the master key lives in Secret Service. To use agenix, sops-nix, or another provisioner without a keyring, configure one file:

```toml
# Read the storage master key from a file
[storage]
key_source = "file"
key_file = "/run/agenix/noctalia-storage-key"
```

The file format and generation steps are under [Encrypted storage master key](/noctalia/configuration/general/#encrypted-storage-master-key).

- With no storage key, live sync continues but events are not read from or written to disk.
- A missing or wrong key keeps the encrypted cache and shows a retry action in Settings.
- If the key cannot be restored or the cache is damaged, **Recover Private Storage** offers a confirmed reset. It also removes saved clipboard history, since both share the master key.
- A configured key file is never modified.

## CalDAV setup

Noctalia discovers calendars from an account or server root, so you do not need each calendar's collection URL.

The account id is the last segment of the table name: `[calendar.account.personal_icloud]` has id `personal_icloud`. Use short ids with lowercase letters, digits, and underscores. It need not match your email or provider account.

1. Declare the account table in TOML.
2. For Secret Service: open **Settings → Calendar → Accounts**, edit the account, enter its app password, and press **Save**.
3. For a file provisioner instead: set `credential_source = "file"` and `password_file` in the table. There is no plaintext password key.

With two-factor authentication, create an app-specific password in the provider's security settings; your normal password usually fails.

- `provider = "icloud"` uses Apple's discovery URL. Do not set `server_url`.
- `provider = "custom"` requires `server_url`, the provider's CalDAV discovery root, not a single calendar collection.
- `calendars = []` syncs every discovered calendar that supports events.
- `calendars = ["id"]` syncs only those collection ids (the decoded last path segment of each calendar URL). Start empty, then narrow after discovery works.

## mTLS (client certificates)

Some CalDAV servers require a client certificate during the TLS handshake. `caldav` accounts support this with two fields:

```toml
# CalDAV account with a client certificate
[calendar.account.secure_dav]
type       = "caldav"
name       = "mTLS Server"
provider   = "custom"
server_url = "https://dav.example.com/"
username   = "me"
credential_source = "file"
password_file    = "/run/agenix/noctalia-caldav"
client_cert_file = "~/pki/client.pem"
client_key_file  = "~/pki/client.key"
```

- `client_cert_file` and `client_key_file` must be set together and point at PEM files. `~` and `$VARS` expand; the result must be absolute.
- The certificate is sent during discovery and every sync. Use an `https://` `server_url`: it is also sent to any HTTPS host a redirect leads to.
- `google`, `ics`, and `vdir` accounts reject these fields.

Certificates in an NSS database (such as `~/.pki/nssdb`, used by Firefox and NetworkManager) must be exported to PEM first:

```sh
certutil -d sql:$HOME/.pki/nssdb -L -n "your-cert-nickname" -a > ~/pki/client.pem
pk12util -o ~/pki/client.p12 -d sql:$HOME/.pki/nssdb -n "your-cert-nickname"
openssl pkcs12 -in ~/pki/client.p12 -nocerts -nodes -out ~/pki/client.key
```

## iCloud

iCloud needs your Apple Account email as `username` and an Apple app-specific password.

1. In Settings, choose **iCloud** and enter the app-specific password in **App Password**.
2. For manual TOML, use `provider = "icloud"` without `server_url`, then enter the password in Settings.

```toml
# Two iCloud accounts
[calendar.account.icloud_personal]
type     = "caldav"
name     = "Personal iCloud"
provider = "icloud"
username = "me@example.com"
calendars = []

[calendar.account.icloud_family]
type     = "caldav"
name     = "Family iCloud"
provider = "icloud"
username = "family@example.com"
calendars = []
```

Do not use a public `.ics` sharing URL or your normal iCloud password.

Common failures:

- `401` or repeated auth failures: regenerate the app-specific password, edit the account in Settings, and save it.
- No events from one calendar: keep `calendars = []` to verify discovery before selecting collection ids.
- Shared calendars may have their own collection ids; `calendars = []` includes them all.

## Google setup

1. In Settings, choose **Google** and press **Save and Connect**. For manual TOML, add a table with `type = "google"`, enable the calendar, then edit the account in **Settings → Calendar → Accounts** and press **Save and Connect**.
2. Approve Google's consent screen in the browser tab; the tab confirms completion.

Tokens come from the Noctalia OAuth broker (`api.noctalia.dev`), so you need no Google Cloud project or client secret. Access is `calendar.readonly`.

:::note
The account id is the last segment of the table name: `[calendar.account.work_google]` has id `work_google`. It must **not** be your Google email; the Google account is chosen during browser authorization.
:::

- If the account later shows as disconnected (revoked or expired), edit it and press **Save and Connect** again.
- By default Noctalia syncs the calendars ticked in Google Calendar's sidebar. After the first sync, the account's **Calendars** list shows every calendar, starting from Google's ticks.
- Changing a toggle saves an explicit `calendars` list that ignores Google's sidebar; calendars added to Google later stay off until ticked. Matching Google's ticks again resets it to `[]`. The list refreshes on every sync.

If Settings reports Secret Service unavailable, start a compatible provider in the same login session and use retry. Noctalia also reopens credentials on its own once the provider appears or unlocks; see [Secret Service & keyrings](/noctalia/configuration/secret-service/).

- Locked or denied: unlock the provider and retry.
- A cancelled prompt is not treated as a missing credential; start the operation again when ready.
- `[shell].offline_mode = true` disables all calendar network traffic. Cached events stay available when the storage key is.

## ICS setup

1. In Settings, choose **ICS URL** and paste a URL to an [iCalendar](https://en.wikipedia.org/wiki/ICalendar) file.
2. For manual TOML, add a table with `type = "ics"` and `server_url`. No other fields are needed.

- `webcal://` and `webcals://` are accepted as aliases for `https://`.
- The URL must be public and return iCalendar data without credentials, not a login or error page.
- When a fetch fails, Noctalia shows the event cache until the URL works again.

## Local directory (vdir / vdirsyncer)

1. In Settings, choose **Local (vdir)**, enter a local account id, and the calendar folder path. `~/...` and absolute paths work.
2. For manual TOML, add a table with `type = "vdir"` and `path`:

```toml
# Local vdir calendars
[calendar.account.local_vdir]
type      = "vdir"
name      = "Local Calendars"
path      = "~/.local/share/calendars"
calendars = [] # empty = all discovered collections
```

Noctalia searches the tree up to 5 levels deep for collections and reads their metadata:

- **Display name**: the `displayname` file, the `X-WR-CALNAME` header in `.ics` files, or the directory name.
- **Color**: the `color` file (hex).
- **Order**: the integer in the `order` file.

Collections are watched with `inotify`. When tools like `vdirsyncer` add, change, or remove `.ics` files, the calendar reloads automatically.
