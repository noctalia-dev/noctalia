The system monitor samples CPU, memory, network, load, temperature, GPU, and disk statistics for bar and desktop `sysmon` widgets and the Control Center System tab. Configure it under `[system.monitor]` or in **Settings → Services**.

```toml
# Default sampling intervals in seconds
[system.monitor]
enabled = true
cpu_temp_sensor_path = ""
cpu_poll_seconds = 2.0
gpu_poll_seconds = 5.0
memory_poll_seconds = 2.0
network_poll_seconds = 3.0
disk_poll_seconds = 10.0
```

| Key                    | Default | Description                                                                                             |
| ---------------------- | ------- | ------------------------------------------------------------------------------------------------------- |
| `enabled`              | `true`  | Run background sampling. When off, widgets and the System tab stay visible but show unavailable values. |
| `cpu_temp_sensor_path` | `""`    | Exact `temp*_input` sysfs file for CPU temperature. Empty = auto-detect.                                |
| `cpu_poll_seconds`     | `2.0`   | CPU usage %, frequency, temperature, and load average (`1` / `5` / `15` min).                           |
| `gpu_poll_seconds`     | `5.0`   | GPU temperature, usage %, and VRAM used/total.                                                          |
| `memory_poll_seconds`  | `2.0`   | RAM usage % and used/total MB.                                                                          |
| `network_poll_seconds` | `3.0`   | Network download and upload throughput.                                                                 |
| `disk_poll_seconds`    | `10.0`  | Disk used/free for paths used by bar `sysmon` widgets, plus swap usage % and used/total MB.             |

Settings → Services → Advanced (intervals, in whole-second steps, when the monitor is enabled).

- Intervals are global, not per widget. Non-zero values are clamped to `1` to `120` seconds; `0` disables that metric group entirely.
- GPU probes run only while a native widget shows a GPU stat or a plugin calls `noctalia.setGpuMonitoring(true)`. Reading `noctalia.systemStats()` alone does not enable them.
- Aggregate network values count only physical interfaces (those with a `/sys/class/net/<interface>/device` link), so tunnels and bridges are not double counted. Without any, as in some containers, all non-loopback interfaces count.
- Graphs (widget **graph** mode and the System tab) scroll at the fastest enabled interval. If every interval is `0`, no history is recorded.

### CPU temperature sensor

Auto-detection prefers known CPU hwmon drivers such as `k10temp`, `zenpower`, and `coretemp`; on AMD this normally picks the `Tctl` sensor (`temp1_input`). To force a sensor:

```toml
# Use a specific hwmon input for CPU temperature
[system.monitor]
cpu_temp_sensor_path = "/sys/class/hwmon/hwmon3/temp1_input"
```

When set, only that file is used. If it is missing, unreadable, not a `temp*_input` file, or unparsable, CPU temperature shows as unavailable.

To list hwmon temperature inputs with driver names, labels, and raw values:

```sh
for h in /sys/class/hwmon/hwmon*; do
  name="$(cat "$h/name" 2>/dev/null || echo unknown)"
  for input in "$h"/temp*_input; do
    [ -e "$input" ] || continue
    base="${input%_input}"
    label="$(cat "${base}_label" 2>/dev/null || basename "$base")"
    value="$(cat "$input" 2>/dev/null || echo unreadable)"
    printf '%s name=%s label=%s raw=%s\n' "$input" "$name" "$label" "$value"
  done
done
```

## Available stats

All widgets and the System tab share one catalog of stats. Each widget picks one with `stat`; desktop graphs take an optional second with `stat2`.

| Value           | Display    | Description                                   | Bar | Desktop |
| --------------- | ---------- | --------------------------------------------- | --- | ------- |
| `cpu_usage`     | `75%`      | CPU utilisation (all cores)                   | ✓   | ✓       |
| `cpu_temp`      | `65°C`     | CPU package temperature                       | ✓   | ✓       |
| `cpu_freq`      | `3.8 GHz`  | Average current CPU frequency                 | ✓   | ✓       |
| `gpu_temp`      | `72°C`     | GPU temperature                               | ✓   | ✓       |
| `gpu_usage`     | `48%`      | GPU utilisation                               | ✓   | ✓       |
| `gpu_vram`      | `42%`      | GPU VRAM usage                                | ✓   | ✓       |
| `ram_used`      | `4.2 GiB`  | RAM used (binary, auto-scaled)                | ✓   | –       |
| `ram_pct`       | `26%`      | RAM used %                                    | ✓   | ✓       |
| `swap_pct`      | `12%`      | Swap used %                                   | ✓   | ✓       |
| `disk_used_pct` | `45%`      | Disk used % for the widget's `path`           | ✓   | –       |
| `disk_used`     | `120 GiB`  | Disk space used for the widget's `path`       | ✓   | –       |
| `disk_free_pct` | `55%`      | Disk free % for the widget's `path`           | ✓   | –       |
| `disk_free`     | `380 GiB`  | Disk space available for the widget's `path`  | ✓   | –       |
| `net_rx`        | `1.2 MB/s` | Network download speed (decimal, auto-scaled) | ✓   | ✓       |
| `net_tx`        | `256 kB/s` | Network upload speed (decimal, auto-scaled)   | ✓   | ✓       |

- A stat whose source is missing (such as VRAM on an integrated GPU) shows as unavailable, not zero. See [GPU data sources](#gpu-data-sources).
- Per-widget `path` selects the mount the four disk stats measure.
- Per-widget `interface` selects the `/proc/net/dev` interface (such as `wlan0` or `enp5s0`) for `net_rx`/`net_tx`; empty = the aggregate total.

## GPU data sources

Noctalia reads GPU statistics from the kernel and from the vendor's management library where one exists. It needs no elevated privileges and never runs `nvidia-smi`, `intel_gpu_top`, or `radeontop`.

| Source                                                                                                    | Used when                                                  | Notes                                                                                                                                                                                                                                       |
| --------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AMD: `amdgpu` sysfs (hwmon temperature, `gpu_busy_percent`, `mem_info_vram_used` / `mem_info_vram_total`) | The kernel `amdgpu` driver is loaded                       | No extra package needed.                                                                                                                                                                                                                    |
| AMD: ROCm SMI (`librocm_smi64.so`)                                                                        | The ROCm runtime is installed                              | Preferred over sysfs; optional.                                                                                                                                                                                                             |
| NVIDIA: NVML (`libnvidia-ml.so.1`)                                                                        | The proprietary driver is installed                        | Provides temperature, usage, and VRAM; temperature falls back to hwmon. Usually in the driver's utilities package (`nvidia-utils` on Arch). Nouveau has no NVML. Skipped while a hybrid laptop's dGPU sleeps; the iGPU is reported instead. |
| Intel: `i915` / `xe` hwmon and per-client DRM statistics                                                  | The `i915` or `xe` driver is loaded                        | Usage is summed per process; see below.                                                                                                                                                                                                     |
| Intel: `xe` device query                                                                                  | A discrete card (such as Intel Arc) on Linux 6.18 or newer | VRAM only. Older kernels report VRAM as unavailable.                                                                                                                                                                                        |

:::note[Integrated GPUs are supported]
Integrated AMD and Intel GPUs report temperature and usage when their drivers expose them. Only `gpu_vram` is unavailable, since shared system memory has no dedicated VRAM.
:::

For NVIDIA, the driver and NVML library must match; `nvidia-utils` does not replace the kernel driver. Check that NVML is visible:

```sh
ldconfig -p | grep 'libnvidia-ml.so.1'
```

Intel usage caveats:

- Other users' processes are not counted.
- The first value appears one `gpu_poll_seconds` interval after startup.
- Media/video engines are not counted, so accelerated video playback can show `0%`.

## Value highlighting

- Bar `sysmon` widgets tint their icon, label, graph line, and gauge fill from their `color` toward their `highlight_color` (see the [`sysmon` widget](/noctalia/bar/widgets/sysmon/)) as a stat rises.
- Below the activity threshold the value keeps its regular color. Crossing it jumps to a small tint, which ramps to the full `highlight_color` at the critical threshold.
- Set a critical threshold to `0` to disable highlighting for that stat.
- `ram_used` and `ram_pct` share the `ram_pct_*` thresholds.

```toml
# Default highlight thresholds
[system.monitor]
cpu_usage_activity_threshold = 50     # %
cpu_usage_critical_threshold = 90     # %
cpu_temp_activity_threshold  = 60     # °C
cpu_temp_critical_threshold  = 85     # °C
cpu_freq_activity_threshold  = 2.5    # GHz
cpu_freq_critical_threshold  = 4.5    # GHz
gpu_temp_activity_threshold  = 60     # °C
gpu_temp_critical_threshold  = 85     # °C
gpu_usage_activity_threshold = 50     # %
gpu_usage_critical_threshold = 95     # %
gpu_vram_activity_threshold  = 50     # %
gpu_vram_critical_threshold  = 90     # %
ram_pct_activity_threshold   = 60     # %
ram_pct_critical_threshold   = 90     # %
swap_pct_activity_threshold  = 20     # %
swap_pct_critical_threshold  = 80     # %
disk_used_pct_activity_threshold = 80 # %
disk_used_pct_critical_threshold = 95 # %
disk_used_activity_threshold     = 80 # %
disk_used_critical_threshold     = 95 # %
disk_free_pct_activity_threshold = 80 # %
disk_free_pct_critical_threshold = 95 # %
disk_free_activity_threshold     = 80 # %
disk_free_critical_threshold     = 95 # %
net_rx_activity_threshold    = 1      # MB/s
net_rx_critical_threshold    = 50     # MB/s
net_tx_activity_threshold    = 1      # MB/s
net_tx_critical_threshold    = 50     # MB/s
```

| Key                                                                     | Default       | Unit | Stat                        |
| ----------------------------------------------------------------------- | ------------- | ---- | --------------------------- |
| `cpu_usage_activity_threshold` / `cpu_usage_critical_threshold`         | `50` / `90`   | %    | CPU usage                   |
| `cpu_temp_activity_threshold` / `cpu_temp_critical_threshold`           | `60` / `85`   | °C   | CPU temperature             |
| `cpu_freq_activity_threshold` / `cpu_freq_critical_threshold`           | `2.5` / `4.5` | GHz  | CPU frequency               |
| `gpu_temp_activity_threshold` / `gpu_temp_critical_threshold`           | `60` / `85`   | °C   | GPU temperature             |
| `gpu_usage_activity_threshold` / `gpu_usage_critical_threshold`         | `50` / `95`   | %    | GPU usage                   |
| `gpu_vram_activity_threshold` / `gpu_vram_critical_threshold`           | `50` / `90`   | %    | GPU VRAM usage              |
| `ram_pct_activity_threshold` / `ram_pct_critical_threshold`             | `60` / `90`   | %    | RAM usage (also `ram_used`) |
| `swap_pct_activity_threshold` / `swap_pct_critical_threshold`           | `20` / `80`   | %    | Swap usage                  |
| `disk_used_pct_activity_threshold` / `disk_used_pct_critical_threshold` | `80` / `95`   | %    | Disk used %                 |
| `disk_used_activity_threshold` / `disk_used_critical_threshold`         | `80` / `95`   | %    | Disk used                   |
| `disk_free_pct_activity_threshold` / `disk_free_pct_critical_threshold` | `80` / `95`   | %    | Disk free %                 |
| `disk_free_activity_threshold` / `disk_free_critical_threshold`         | `80` / `95`   | %    | Disk free                   |
| `net_rx_activity_threshold` / `net_rx_critical_threshold`               | `1` / `50`    | MB/s | Network download            |
| `net_tx_activity_threshold` / `net_tx_critical_threshold`               | `1` / `50`    | MB/s | Network upload              |

Settings → Services (when the monitor is enabled). Each stat has a dual-handle slider: left sets the activity threshold, right the critical one, and the handles cannot cross.
