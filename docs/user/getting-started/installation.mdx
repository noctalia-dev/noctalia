Noctalia is available on the following distributions. Choose your platform below, or use the manual installation method on another Linux distribution.

- [Arch Linux](#arch)
- [NixOS](/noctalia/getting-started/nixos/)
- [Fedora](#fedora)
- [openSUSE](#opensuse)
- [Gentoo](#gentoo)
- [GNU Guix](#guix)
- [Debian](#debian) (including Ubuntu)
- [Chimera Linux](#chimera)

You can also [install manually](#manual-install) on any other Linux distribution.

:::note[Package ownership]
The Noctalia team maintains the **manual installation method**. Official distribution packages are maintained through their distributions' own packaging processes; other repositories listed here are community-maintained. Review a third-party repository before installing from it.
:::

<details>
  <summary>Already using Noctalia Shell v4?</summary>

  Noctalia v5 is a fresh install, not an automatic upgrade from the Quickshell-based v4 implementation. Its package and configuration files are separate, so both versions can be installed at the same time on most distributions, but v4 settings are not migrated.

  Only your **compositor keybinds** need attention. Update any bindings that launch the Noctalia launcher, panels, settings UI, or other commands when switching between versions.
</details>

## Arch Linux {#arch}

Noctalia is available in the [extra] repository.

```bash
sudo pacman -S noctalia
```
---

## Fedora {#fedora}

Noctalia is available from the default repos for Fedora 44 and up.

**Step 1**: Install noctalia

```bash
sudo dnf install noctalia
```

An alternate version using git snapshots is available from the [LionHeartP Copr](https://copr.fedorainfracloud.org/coprs/lionheartp/Hyprland/) repository.

**Step 1**: Enable the repository

```bash
sudo dnf copr enable lionheartp/Hyprland 
```

**Step 2**: Install noctalia

```bash
sudo dnf install noctalia-git
```

## openSUSE {#opensuse}

Noctalia is available via [home:neifua:Noctalia](https://build.opensuse.org/package/show/home:neifua:Noctalia/noctalia-git) repository on the openSUSE Build Service.

**Step 1**: Add the OBS repository

<Tabs>
  <TabItem label="Tumbleweed">
    ```bash
	sudo zypper addrepo --refresh --name noctalia-v5 https://download.opensuse.org/repositories/home:neifua:Noctalia/openSUSE_Tumbleweed/home:neifua:Noctalia.repo
    ```
  </TabItem>
  <TabItem label="Slowroll">
    ```bash
	sudo zypper addrepo --refresh --name noctalia-v5 https://download.opensuse.org/repositories/home:neifua:Noctalia/openSUSE_Slowroll/home:neifua:Noctalia.repo
    ```
  </TabItem>
</Tabs>


**Step 2**: Refresh and install noctalia:

<Tabs>
	<TabItem label="Stable (recommended)">
	```bash
	sudo zypper refresh
	sudo zypper install noctalia
	```
	</TabItem>
	<TabItem label="Unstable">
	```bash
	sudo zypper refresh
	sudo zypper install noctalia-git
	```
	</TabItem>
</Tabs>

:::note
v5 will only be available for **Tumbleweed** and **Slowroll**. **Leap 16.0** is unable to build because *sdbus-c++* is still on v1.6.0 while v5 requires >= v2.x.x

- **[Stable version](https://build.opensuse.org/package/show/home:neifua:Noctalia/noctalia)**: Updated when a new release is tagged
- **[Unstable version](https://build.opensuse.org/package/show/home:neifua:Noctalia/noctalia-git)**: Automatically rebuilt on OBS whenever a new commit is pushed
:::

## Gentoo {#gentoo}

Noctalia is available in the [GURU](https://wiki.gentoo.org/wiki/Project:GURU) overlay.

**Step 1**: Enable and sync the overlay as read in [Project:GURU/Information_for_End_Users](https://wiki.gentoo.org/wiki/Project:GURU/Information_for_End_Users).

**Step 2**: [Unmask](https://wiki.gentoo.org/wiki/Live_ebuilds#Unmasking_live_ebuilds) the `gui-apps/noctalia` package:

```
gui-apps/noctalia ~amd64
```

**Step 3**: Emerge the package:

```bash
emerge --ask gui-apps/noctalia
```

## GNU Guix {#guix}

Noctalia is available in the main Guix repository as the package `noctalia-shell`. Simply add `(gnu packages window-management)` to your list of imported modules, then add `noctalia-shell` to your list of packages.

Due to the fast pace of development on Noctalia, the main Guix channel is likely to lag behind in version. If you don't wish to wait for it to update then you have two alternative channels. Do note that with both options you will be compiling the package yourself, because only the main Guix channel provides substitutes for it.

<Tabs>
  <TabItem label="Noctalia channel">
  
  The Git repository of Noctalia is also available as a [Guix channel](https://guix.gnu.org/manual/devel/en/html_node/Channels.html).  It provides a `(noctalia)` module with the `noctalia-git` package. 
  
  Do note that since this is a git package, there might be times (though rare) where it fails to compile when either dependencies or something about the build process changes. If that happens you might want to [pin the channel](https://guix.gnu.org/manual/devel/en/html_node/Replicating-Guix.html) to an older working commit by adding `(commit "[full commit hash]")` to the channel definition.
  
  ```scheme
  (channel
    (name 'noctalia)
    (url "https://github.com/noctalia-dev/noctalia")
    (branch "main"))
  ```
  
  Whenver you run `guix pull` you will get the latest commit of noctalia, which will start compiling and be available for use when you reconfigure your system or home environment, whichever you added the `noctalia-shell` package to. You can use `guix pull --select=noctalia` if you wish to update only noctalia without needing to pull your other channels.
  </TabItem>
  <TabItem label="Midnight channel">
  
  The third-party [`midnight`](https://codeberg.org/stampede/midnight) guix channel provides the `noctalia` package under the module `(midnight packages noctalia)`. It provides up-to-date stable releases of noctalia for those who prefer that over a git package.
  
  ```scheme
  (channel
    (name 'midnight)
    (url "https://codeberg.org/stampede/midnight.git")
    (branch "main")
    (introduction
      (make-channel-introduction
        "d97d1568954cfcbf543c9fcdfd5771e2b730ae19"
        (openpgp-fingerprint
          "640A 2C3C E948 22D3 394B 40C3 CAFA EECA 00FF 9B1E"))))
  ```
  
  </TabItem>
</Tabs>

## Debian {#debian}

Noctalia provides an APT repository for Debian-based distributions.

**Step 1**: Install the repository signing key

```bash
wget https://pkg.noctalia.dev/deb/nickh-archive-keyring.deb && sudo dpkg -i nickh-archive-keyring.deb
```

**Step 2**: Add the repository

<Tabs>
  <TabItem label="Debian Trixie">
    ```bash
    sudo wget -O /etc/apt/sources.list.d/noctalia-trixie.sources https://pkg.noctalia.dev/deb/noctalia-trixie.sources
    ```
  </TabItem>
  <TabItem label="Debian Sid">
    ```bash
    sudo wget -O /etc/apt/sources.list.d/noctalia-unstable.sources https://pkg.noctalia.dev/deb/noctalia-unstable.sources
    ```
  </TabItem>
  <TabItem label="Ubuntu 26.04">
    ```bash
    sudo wget -O /etc/apt/sources.list.d/noctalia-resolute.sources https://pkg.noctalia.dev/deb/noctalia-resolute.sources
    ```
  </TabItem>
</Tabs>

**Step 3**: Install noctalia

```bash
sudo apt update
sudo apt install noctalia
```

You can also install the `noctalia-greeter`, `umbriel`, and `xdg-desktop-portal-umbriel` packages.

:::note
The APT repository provides `amd64` and `arm64` packages only.
:::


***Configuring `noctalia-greeter`***
<ol>
<li>
If already using `greetd`, no configuration is required. Just restart greetd with:

```bash
sudo systemctl restart greetd
```
</li>
<li>
If not currently using `greetd`

First stop and disable your current display manager. Eg:

```bash
sudo systemctl disable --now gdm3
```
Then enable and start `greetd`. Eg:

```bash
sudo systemctl enable --now greetd
```
</li>
</ol>

## Chimera Linux {#chimera}

Noctalia is available in Chimera's `user` repository.

Run the following commands as root.

**Step 1**: Enable the `user` repository if it isn't already:

```bash
apk add chimera-repo-user
```

**Step 2**: Refresh the package indexes and install Noctalia:

```bash
apk update
apk add noctalia
```

## Manual Installation {#manual-install}

:::caution[Not Recommended]
Manual installation has **no easy upgrade path**. You will need to manually download and replace files for each update. We strongly recommend using a package manager ([Arch](#arch), [Fedora](#fedora)) whenever possible.
:::

If you prefer to install Noctalia locally or want more control over the installation process, you can install it manually to your user configuration directory. This method works on any Linux distribution.

**Step 1**: Sync and install dependencies

<Tabs>
  <TabItem label="Arch">
    ```bash
    sudo pacman -S meson gcc just \
      wayland wayland-protocols \
      libglvnd freetype2 fontconfig \
      cairo pango harfbuzz \
      libxkbcommon glib2 \
      libsecret libsodium \
      sdbus-cpp libpipewire wireplumber polkit \
      pam curl libwebp libjxl libsndfile librsvg \
      libqalculate libxml2 \
      md4c tomlplusplus \
      nlohmann-json stb \
      jemalloc
    ```
  </TabItem>
  <TabItem label="Fedora">
    ```bash
    sudo dnf install meson gcc-c++ just \
      wayland-devel wayland-protocols-devel \
      libEGL-devel mesa-libGLES-devel \
      freetype-devel fontconfig-devel \
      cairo-devel pango-devel harfbuzz-devel \
      libxkbcommon-devel glib2-devel \
      libsecret-devel libsodium-devel \
      sdbus-cpp-devel pipewire-devel wireplumber-devel \
      pam-devel polkit-devel libcurl-devel libwebp-devel libjxl-devel libsndfile-devel librsvg2-devel \
      libqalculate-devel libxml2-devel \
      md4c-devel tomlplusplus-devel \
      json-devel stb_image_resize2-devel stb_image_write-devel \
      jemalloc-devel
    ```
  </TabItem>
  <TabItem label="Debian/Ubuntu">
    ```bash
    sudo apt install just meson libwayland-dev \
      wayland-protocols libfreetype-dev libfontconfig-dev \
      libcairo2-dev libpango1.0-dev librsvg2-dev libxkbcommon-dev \
      libepoxy-dev libgles-dev libwebp-dev libcurl4-gnutls-dev \
      libmd4c-dev nlohmann-json3-dev libsdbus-c++-dev libsecret-1-dev \
      libsodium-dev libstb-dev libtomlplusplus-dev \
      libpipewire-0.3-dev libpam0g-dev libpolkit-agent-1-dev \
      libpolkit-gobject-1-dev libqalculate-dev libwireplumber-0.5-dev \
      libxml2-dev libjemalloc-dev git

    ```
  </TabItem>
</Tabs>

Vendored dependencies, with no system package needed: `Wuffs`,
`Luau`, `fzy`, and Material Color Utilities.

System packages required beyond the Wayland/GL stack: `libwebp` handles WebP decoding and thumbnail encoding. Wuffs
handles the other supported raster image formats.


Polkit agent support requires development files that provide the `polkit-agent-1` and `polkit-gobject-1` pkg-config
modules. Some distros ship these in the runtime `polkit` package, while split-package distros use names such as
`polkit-devel`, `polkit-dev`, or `libpolkit-agent-1-dev` / `libpolkit-gobject-1-dev`.

**Optional:** installing `jemalloc` (Fedora: `jemalloc-devel`, Arch: `jemalloc`, Debian/Ubuntu: `libjemalloc-dev`, Void:
`jemalloc`) reduces memory fragmentation in long-running sessions. On glibc systems it is used automatically when
detected. Use Meson's `-Djemalloc=enabled` or `-Djemalloc=disabled` option to require or disable it explicitly.

Sanitizer runtime packages are only needed for ASan/UBSan builds configured with `just configure asan`.

**Step 2**: Prepare directory

```bash
git clone https://github.com/noctalia-dev/noctalia --branch main
cd noctalia
```

**Step 3**: Building and installing Noctalia

Requires [just](https://github.com/casey/just) and [meson](https://mesonbuild.com/).

<Tabs>
  <TabItem label="Release Mode">
		```bash
	# Optimized release build in build-release/
	just configure release
	just build release

	# Install the selected build mode. This does not build or reconfigure.
	sudo just install release
		```

	Pass a prefix to `configure` to install somewhere other than `/usr/local`:

	```bash
	just configure release "$HOME/.local"
	just build release
	just install release
	```

	To remove files installed from a build directory, run `just uninstall release`.
  </TabItem>
  <TabItem label="Debug Mode">
		```bash
	# Debug build in build-debug/ for local development and troubleshooting.
	just configure
	just build

	# Test your local debug build with 
	just run
		```
  </TabItem>
</Tabs>

Meson installs the binary and shipped assets using the normal prefix layout:

```text
/usr/local/bin/noctalia
/usr/local/share/noctalia/assets/...
```

Noctalia needs the shipped `assets/` tree at runtime. Copying only the `noctalia` binary is not enough.

Portable bundle layouts are also supported:

```text
bundle/
  noctalia
  assets/
```

```text
bundle/
  bin/noctalia
  share/noctalia/assets/
```

See [PACKAGING.md](https://github.com/noctalia-dev/noctalia/blob/main/PACKAGING.md#runtime-asset-lookup) for the full runtime asset lookup order.
