The `[wallpaper]` section sets where wallpapers come from, how they fill each monitor, how they change, and automatic rotation. The wallpaper picker panel edits most of these live.

```toml
# Defaults, with a default wallpaper set
[wallpaper]
enabled = true
fill_mode = "crop"
fill_color = "#111111"
directory = ""

[wallpaper.default]
path = "~/Pictures/Wallpapers/default.png"
```

## Wallpaper directory

```toml
# Theme-aware and per-monitor folders
[wallpaper]
directory = ""
directory_light = "/home/user/Wallpapers/Light"
directory_dark = "/home/user/Wallpapers/Dark"
per_monitor_directories = true

[wallpaper.monitor.DP-2]
enabled = false
fill_color = "#202020"
directory = "/home/user/Wallpapers/Vertical"
directory_light = "/home/user/Wallpapers/Vertical/Light"
directory_dark = "/home/user/Wallpapers/Vertical/Dark"
```

| Key                       | Default | Description                                                                                                                                                              |
| ------------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `enabled`                 | `true`  | Draw wallpapers.                                                                                                                                                         |
| `directory`               | `""`    | Folder browsed by the picker, launcher provider, and rotation. Empty uses the XDG Pictures directory (`XDG_PICTURES_DIR` or `user-dirs.dirs`), then `~/Pictures`.        |
| `directory_light`         | –       | Folder used when the theme mode is Light. Missing or **Auto** mode falls back to `directory`.                                                                            |
| `directory_dark`          | –       | Folder used when the theme mode is Dark. Missing or **Auto** mode falls back to `directory`.                                                                             |
| `per_monitor_directories` | `false` | Enable `[wallpaper.monitor.<name>]` directory overrides. When `false`, all monitors share the global directories.                                                        |
| `default.path`            | –       | Initial wallpaper for every output (`[wallpaper.default]`). Choosing a wallpaper in the UI or IPC writes this key to `settings.toml`, which overrides declarative files. |

`[wallpaper.monitor.<name>]` uses the same match rules as bar monitor overrides. It accepts `enabled`, `fill_color`, `directory`, `directory_light`, and `directory_dark`; directory keys apply only with `per_monitor_directories = true`.

- With no wallpaper configured, Noctalia shows its bundled wallpaper. This fallback is never written to `settings.toml`, so a wallpaper declared later in `~/.config/noctalia/*.toml` still applies.
- The picker shows thumbnails from the resolved folder and highlights the wallpaper on the selected monitor. In the **ALL** view it highlights the default wallpaper.
- Selecting a monitor in the picker toolbar switches to that monitor's resolved folder, falling back to the global one.
- Clicking a tile writes the path to `settings.toml` and applies it. With **ALL** selected, it applies to every monitor.
- Picking a solid color stores a source path such as `color:#FF00FF` and uses the same transitions as images.
- The picker's fill mode selector changes the global `fill_mode`, the same as the Settings entry.
- Recursive scans (picker with **Flatten**, launcher provider, rotation with `recursive = true`) follow symlinks to folders. Each real folder is scanned once, so loops and duplicate links don't repeat images.

## Fill and formats

| Key          | Default     | Description                                                                                                                                                                                                                                                                         |
| ------------ | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `fill_mode`  | `"crop"`    | How each wallpaper is framed: `center`, `crop`, `fit`, `stretch`, `repeat`, or `span`. See [Fill modes](#fill-modes).                                                                                                                                                               |
| `fill_color` | `"#111111"` | Color behind image wallpapers and in uncovered areas for `center` and `fit`. Accepts a palette role such as `surface` or `primary` (preferred, follows the palette) or `#RGB`, `#RGBA`, `#RRGGBB`, `#RRGGBBAA`. Invalid values are config errors. Monitor overrides may set it too. |

### Image formats

Wallpapers can be PNG, JPEG, WebP, JPEG XL, BMP, GIF, HEIC, HEIF, or AVIF files.

- HEIC, HEIF, and AVIF need `libheif` at runtime, with an AV1 decoder plugin (dav1d or aom) for AVIF and an HEVC plugin (such as libde265) for HEIC.
- On Fedora the HEVC plugin comes from RPM Fusion's `libheif-freeworld`.
- Without libheif those files still show in the picker but fail to load, and the log says HEIF/AVIF decoding requires libheif.

### Fill modes

- **center** - the image at its native size, centered; `fill_color` shows around it.
- **crop** - scaled to cover the whole output, cropping any overflow (default).
- **fit** - scaled to fit entirely within the output; `fill_color` fills the letterbox.
- **stretch** - scaled to the output's exact dimensions, ignoring aspect ratio.
- **repeat** - tiled at native size across the output.
- **span** - one image across the whole multi-monitor desktop, honoring each output's logical position, so a wide wallpaper flows across screens. Single-monitor setups behave like `crop`; slices refresh when a monitor moves, is added, or is removed.

### Large images

:::note
Wallpapers decode in the background, so a huge file never freezes the shell; the previous wallpaper stays until the new one is ready. For `crop`, `fit`, `stretch` and `span`, an image much larger than the output is downscaled in halves with no visible difference, saving VRAM (a 16384×9216 image on 1080p is kept at 2048×1152). `center`, `repeat`, and `shell.disable_mipmaps = true` keep full resolution.
:::

## Transitions

```toml
# Random effect from the pool on each change
[wallpaper]
transition = ["fade", "wipe", "disc", "stripes", "zoom", "honeycomb", "vortex", "pixel", "diamond", "golden", "melt", "crt"]
transition_duration = 1500
edge_smoothness = 0.3
transition_on_startup = false
sync_transitions = true
```

| Key                     | Default     | Description                                                                                                                                                           |
| ----------------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `transition`            | all effects | Effects picked at random each change: `fade`, `wipe`, `disc`, `stripes`, `zoom`, `honeycomb`, `vortex`, `pixel`, `diamond`, `golden`, `melt`, `crt`. Omit to use all. |
| `transition_duration`   | `1500`      | Transition length in milliseconds.                                                                                                                                    |
| `edge_smoothness`       | `0.3`       | Softness of effect edges, `0.0`–`1.0`.                                                                                                                                |
| `transition_on_startup` | `false`     | Animate in the first wallpaper from black at shell startup (v4 behavior). When `false` it appears immediately; later changes always transition.                       |
| `sync_transitions`      | `true`      | All monitors use the same effect and parameters per change. `false` lets each monitor pick its own.                                                                   |

## Automatic rotation

```toml
# Rotate every 30 minutes
[wallpaper.automation]
enabled = false
interval_seconds = 1800
order = "random"
recursive = false
pause_on_fullscreen = false
```

| Key                   | Default    | Description                                                                                                                            |
| --------------------- | ---------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `enabled`             | `false`    | Pick a wallpaper at startup, then every interval, applied to all outputs in sync.                                                      |
| `interval_seconds`    | `1800`     | Seconds between changes.                                                                                                               |
| `order`               | `"random"` | `random` picks any image; `alphabetical` sorts paths case-insensitively and advances one each cycle, wrapping.                         |
| `recursive`           | `false`    | Include subfolders when picking.                                                                                                       |
| `pause_on_fullscreen` | `false`    | Hold rotation while any window is fullscreen; a due switch happens when it leaves fullscreen. Needs `wlr-foreign-toplevel-management`. |

- Rotation uses the same resolved folder as the picker. With `per_monitor_directories = true`, each monitor picks from its own folder.
- Rotation always holds while the lock screen is up.

## Favorites

The wallpaper panel manages image favorites through tile stars; there is no separate Settings page. Star a tile to bookmark it, star again to remove it.

- Favorites appear at the **top of the browse grid** at the wallpaper root. Inside a subfolder, only favorites in that folder (or under it with **Flatten**) are pinned.
- Solid `color:#RRGGBB` favorites can only be declared in config and appear only at the root. The panel can show and remove them but not create them.
- The monitor selector (**ALL** or one output) works the same for favorites and browse entries.

```toml
# One image and one color favorite
[[wallpaper.favorite]]
path = "/home/user/Wallpapers/sunset.jpg"
theme_mode = "auto"
palette_source = "wallpaper"
wallpaper_scheme = "m3-content"

[[wallpaper.favorite]]
path = "color:#1a1a2e"
theme_mode = "dark"
palette_source = "builtin"
builtin_palette = "Noctalia"
```

| Key                | Description                                                           |
| ------------------ | --------------------------------------------------------------------- |
| `path`             | Image path or `color:#RRGGBB`.                                        |
| `theme_mode`       | Optional: `auto`, `light`, or `dark`.                                 |
| `palette_source`   | Optional: `builtin`, `wallpaper`, `community`, or `custom`.           |
| `wallpaper_scheme` | Scheme when `palette_source = "wallpaper"`, for example `m3-content`. |
| `builtin_palette`  | Palette name when `palette_source = "builtin"`.                       |

- Image paths may start with `~/` and use `$NAME` or `${NAME}` from Noctalia's environment; unset variables expand to nothing.
- `XDG_PICTURES_DIR` is usually not exported, so prefer `~/Pictures/...` unless you set it yourself as an absolute path.
- Paths expand at load and stay as written when the panel saves; images starred in the panel are saved with absolute paths.
- The **Theme** and **Colors** row under the toolbar sets a live global theme override when no favorite is selected. With a favorite selected, it updates that favorite's preset and re-applies it.
- Starring an image saves only its path, unless it is the current wallpaper on the selected monitor: then the active `theme_mode`, `palette_source`, and palette are saved too.
- Clicking a favorite applies its stored theme settings; a favorite without `theme_mode` or `palette_source` leaves those unchanged.

## Backdrop

The backdrop renders a blurred, tinted copy of the wallpaper as a layer-shell surface for compositor overview modes, such as niri's overview. It is disabled by default.

```toml
# Enable the backdrop
[backdrop]
enabled = false
blur_intensity = 0.5
tint_intensity = 0.3
```

| Key              | Default | Description                               |
| ---------------- | ------- | ----------------------------------------- |
| `enabled`        | `false` | Render the backdrop surface.              |
| `blur_intensity` | `0.5`   | `0.0` no blur to `1.0` maximum blur.      |
| `tint_intensity` | `0.3`   | `0.0` no tint to `1.0` fully opaque tint. |

To show it in niri's overview, add a layer rule to your niri config:

```kdl
layer-rule {
    match namespace="^noctalia-backdrop"
    place-within-backdrop true
}
```

- The tint color is `palette.surface` and is not configurable.
- When enabled, backdrop surfaces and wallpaper textures stay in GPU memory for the shell's lifetime.
